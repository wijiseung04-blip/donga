# 오픈소스 라이선스 비교 분석

주요 오픈소스 프로젝트 3개의 라이선스를 비교하고, 이 저장소(donga)의 라이선스 선택 기준을 정리합니다.

## 1. 비교 대상

| 프로젝트 | 분야 | 라이선스 | 계열 |
|---|---|---|---|
| [React](https://github.com/facebook/react) | 웹 UI 라이브러리 | MIT | Permissive |
| [Kubernetes](https://github.com/kubernetes/kubernetes) | 컨테이너 오케스트레이션 | Apache License 2.0 | Permissive (특허 조항 포함) |
| [Linux Kernel](https://github.com/torvalds/linux) | 운영체제 커널 | GPL-2.0 | Strong Copyleft |

## 2. 라이선스별 조건 비교

| 항목 | MIT | Apache 2.0 | GPL-2.0 |
|---|---|---|---|
| 상업적 사용 | 허용 | 허용 | 허용 |
| 수정·재배포 | 허용 | 허용 | 허용 |
| 저작권·라이선스 고지 | 필수 | 필수 | 필수 |
| 변경 사항 명시 | 의무 없음 | 수정한 파일에 명시 | 수정 내용·날짜 명시 |
| 파생물 소스 공개 | 의무 없음 | 의무 없음 | **배포 시 같은 라이선스로 공개** |
| 특허 허락 | 명시 없음 | **명시적 특허 허락 + 특허 소송 시 허락 종료** | 명시 없음 |
| 상표 사용 | 명시 없음 | 허락하지 않음 | 명시 없음 |

## 3. 프로젝트별 선택 이유 분석

### React — MIT
- 라이브러리가 최대한 많은 서비스(상용 포함)에 쓰이는 것이 목표라, 조건이 가장 단순한 라이선스를 택했다.
- 2017년 이전에는 BSD + 특허 조항(PATENTS) 조합이었으나, 특허 조항에 대한 기업·재단(예: Apache 재단)의 반발로 MIT로 변경했다. 라이선스가 생태계 채택에 직접 영향을 준 사례다.

### Kubernetes — Apache 2.0
- Google, Red Hat, Microsoft 등 많은 기업이 함께 기여하는 프로젝트라, 기여자 간 특허 분쟁을 막는 명시적 특허 허락 조항이 중요했다.
- CNCF(Cloud Native Computing Foundation) 프로젝트의 기본 라이선스이기도 하다.

### Linux Kernel — GPL-2.0
- 커널을 수정해 배포하는 기업도 수정한 소스를 공개해야 하므로, 개선 사항이 커뮤니티로 돌아오는 구조를 만든다.
- 이 "공유 강제"가 수많은 기업의 드라이버·개선 코드를 커널 본체로 모으는 원동력이 되었다.

## 4. 라이선스 선택 기준

강의의 결정 트리를 기준으로 질문을 순서대로 적용한다.

| 질문 | 예 → | 아니오 → |
|---|---|---|
| Q1. 상업적 사용을 허용할 것인가? | Q2로 | 비상업 라이선스(CC-BY-NC 등) |
| Q2. 파생물에도 소스 공개를 강제할 것인가? | GPL / AGPL | Q3로 |
| Q3. 기여자 간 특허 분쟁 방지가 필요한가? | Apache 2.0 | MIT |

추가로 고려할 점:
- **의존성 호환성**: GPL 코드를 가져다 쓰면 내 프로젝트도 GPL이 되어야 한다. 반대로 MIT·Apache 코드는 대부분의 라이선스와 함께 쓸 수 있다.
- **기여자 구성**: 여러 기업이 기여한다면 특허 조항이 있는 Apache 2.0이 안전하다.
- **목표**: 널리 쓰이는 것이 목표면 Permissive, 개선 사항의 환원이 목표면 Copyleft.

## 5. donga의 선택: MIT

| 질문 | donga의 답 | 결과 |
|---|---|---|
| Q1. 상업적 사용 허용? | 예. 학습 자료이므로 누구나 자유롭게 쓰길 원함 | Q2로 |
| Q2. 파생물 소스 공개 강제? | 아니오. 재사용 장벽을 낮추는 것이 목적 | Q3로 |
| Q3. 특허 분쟁 방지 필요? | 아니오. 1인 개인 저장소이고 특허 대상 기술이 없음 | **MIT** |

협업자가 늘거나 기업이 기여하게 되면 Apache 2.0으로 바꾸는 것을 검토한다.
